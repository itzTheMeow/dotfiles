# AGENTS.md

Guidance for AI agents working in this repository. This is a Nix flake-based
NixOS configuration for personal machines.

## Overview

- Flake: `/home/*/.dotfiles/flake.nix` (or wherever cloned). Pure flake, no flake-utils magic beyond `eachDefaultSystem`.
- Single repo manages: NixOS hosts, home-manager configs, custom packages/overlays, Go secret-generation tooling, and GitHub/Forgejo CI.
- Everything is declarative where possible; secrets come from 1Password via SOPS (not committed).

## Tooling

- **Use the `nixos` MCP server for ALL nixpkgs/module/package lookups** — packages, NixOS / home-manager / nixvim / darwin options, flakes, channels, /nix/store paths, version history. It queries live APIs (search.nixos.org, NixHub, FlakeHub) and is far more current than training data or `nix search`. Trigger it on any mention of a package name, attribute path, option, channel, or store path — even when you think you know the answer (indexes can be stale too; when a version matters, verify against the flake-locked revisions in `flake.lock`).

## Directory layout

- `flake.nix` — thin glue: defines inputs, merges the satellite repo's (`nvstly`) hosts/apps data in, and calls the factory (`entrypoint.nix`), which defines `nixosConfigurations`, `homeConfigurations`, `packages`, the treefmt `formatter`, and the `checks.formatting` check.
- `nixos/<host>/` — per-host config. Auto-imports every `.nix` file and every subdirectory in the host dir (via `entrypoint.nix`). Also defines the `features.nix` list for that host.
- `nixos/common.nix` — shared config imported by every host.
- `nixos/_common/` — NixOS modules shared by all hosts (imported automatically; `*.hm.nix` files are excluded since those are home-manager modules). Holds the shared ssh client config (`ssh.nix` — machines + the `"*"` 1password block) and code-host git config (`git.nix` — github/forgejo identities + code hosts), each a single module whose HM part is an inline `importUser` function, see below.
- `nixos/_types/` — device-type configs (`console`, `desktop`, `external`, `headless`, `kde`). Imported based on `host.type` from the hosts table; nested types are all included (e.g. `["desktop" "kde"]`).
- `nixos/_features/<feature>/` — optional feature modules enabled per-host via `nixos/<host>/features.nix`. Only enabled features get imported. Feature dirs may hold extra files (e.g. `package.nix`, artifacts).
- `nixos/_features/gaming/hells-kitchen` etc. — some features are nested dirs.
- `home/<host>.nix` — home-manager config per host; `home/common/` — shared home-manager modules.
- `home/programs/` — reusable home-manager program configs.
- `xelib/` — repo "library": `hosts.nix` (host table with tailscale IPs, usernames, ports), `globals.nix` (global settings), `default.nix` (helper functions like `dns`, `apps`, `mkSSHConfig`/`mkSSHSecrets` — emit `programs.ssh.settings` blocks + NixOS-side ssh-pubkey SOPS secrets + kitty launchers gated to desktop hosts), `opsecrets.nix` (SOPS opSecrets module).
- `modules/` — custom NixOS options: `apps`, `dnszones`, `home-manager`, `nginx`, `persist`, `sops`. Loaded via `umport` (nypkgs) in the factory (`entrypoint.nix`). `*.hm.nix` files here are split off by the factory and loaded as home-manager **sharedModules** (real HM args — `config`/`lib` are the HM side, unlike the nixos-tree `importUser` bridge); every other `.nix` file is loaded as a NixOS module. Shared HM modules run for every user incl. root, so guard host-specific behavior (e.g. `modules/plasma-favorites.hm.nix` no-ops unless plasma is enabled and a favorites list is set).
- `overlays/` — custom package overlays, applied to nixpkgs. One entry per package: either a `<name>.nix` file or a `<name>/` dir with `default.nix`, each a `final: prev:` fn using `final.callPackage`. Package sources (Go modules, plugin/source dirs, `just` recipes, patches) live alongside in the same dir (e.g. `xela-nx/` wraps its `nx.just`, `sops-build-secrets/` and `xela-download-organizer/` hold Go tools, `zed/` holds its patch). Packages land directly on `pkgs` (`pkgs.xela-nx`, `pkgs.siyuan-op-unlock`, `pkgs.xela-wine-prefix`, ...).
- `scripts/` — shell scripts used by the config.
- `sops/` — generated secret files (per-host), produced by the Go tool. Do not hand-edit **or delete** them; stale files get removed/regenerated by the go tool on its next run.
- `local/` — machine-specific override configs (`nixos.nix`, `home-manager.nix`), committed as stubs; hide local edits via `git update-index --skip-worktree`. Imported via the factory's `localDir` param. **Imports are unconditional** — pure-eval `pathExists` can't see untracked files, so optionalImport-style presence checks silently diverge local vs CI evals; a missing stub should stay a loud eval error.
- `.forgejo/workflows/` and `.github/workflows/` — CI (formatting; building all hosts into a binary cache).

## Key mechanisms

- **Hosts table (`xelib/hosts.nix`)**: single source for per-host data: username, full name, tailscale `ip`, `type` (list of device types), accent color, ports, public-key URI, backup cadence. Access via `xelib.hosts.<hostname>`. The factory merges the **satellite repo's table in on top** (nvstly: jade/odroid/raspberrypi — same schema, defined in that repo's `hosts.nix`), so external hosts are resolvable anywhere `xelib.hosts` is. `xelib.externalHosts` holds just the satellite entries (drives ssh entries in `_common/ssh.nix`); `xelib.externalApps`/`externalRecords` (from the satellite repo's `apps.nix`) feed the headscale magicdns conversion in `nixos/ehrman/headscale` — satellite apps are never merged into `config.apps`.
- **`apps` module (`modules/apps.nix`)**: define apps as attrsets (`apps.<name> = { port, domain, ... }`). Auto-wires nginx proxies and DNS zones, and it feeds the homepage. `xelib.apps` aggregates from all hosts.
  - **Always reference derived accessors** (`config.apps.<name>.ip`, `.portString`, `.url`, `.host`, `.domain`) instead of local port/ip variables when wiring a service. They resolve automatically: `ip` → the tailscale IP of the host (`xelib.hosts.<host>.ip`), `portString` → `toString .port`, `url` → `https://<domain>` when `domain` is set.
  - **Bind services to `config.apps.<name>.ip`** (the tailscale IP) for anything reachable from other hosts, not `127.0.0.1` — except where nginx alone needs to reach it, in which case binding to the app IP is still fine since nginx proxies by host. Conversely, **non-user-facing internal ports** (e.g. Garage `rpc`/`admin`) should bind to `127.0.0.1` when nothing on another host needs them.
  - `name`/`description`/`icon` are **only for homepage display** — omit unless the app is added to the homepage `services` list (in `homepage/default.nix`). `name` auto-derives to the title-cased attr-name if omitted.
  - Extra per-app metadata goes in `details` (a free-form attrs, e.g. `config.apps.<name>.details.buckets = [...]`), used for extra ports/params not covered by the core fields.
- **`nginx` module (`modules/nginx.nix`)**: `nginx.proxy.<domain>` creates an nginx vhost (docs: `target`, `local`, `allowedHosts`, `anubis`, `oidcGroups`...). Non-local domains get ACME certs; `.xela`/`.internal` domains are treated as local (tailscale-only, self-signed/step-ca cert). Local proxies also auto-get a MagicDNS `A` record to their `target.host` (ehrman's headscale emits one `extra_records` entry per local proxy), so `enableDNS` is only for public zones.
- **`persist` module (`modules/persist.nix`)**: declarative btrfs persistence/impermanence. `persist.ed.<name>` = subvolume to persist, `persist.sync` = syncthing dirs. Wipe-on-boot supported.
- **Features list**: `nixos/<host>/features.nix` returns a list of feature names; only those get imported from `nixos/_features/`.
- **Home-manager modules in the nixos tree**: NixOS modules wire HM modules via `home-manager.imports.<user>`, `home-manager.importUser` (host user only), or `home-manager.importAll` (host user + root). Entries are either module **paths** or **inline `(hm: {...})` functions**, e.g. `home-manager.importUser = [ (hm: { ... }) ]` or `home-manager.importUser = [ ./ssh.hm.nix ]`. If the HM part is simple enough (no other file needs it, it's just a few options), **prefer the inline function over a standalone `*.hm.nix` file** — the ssh config (`nixos/_common/ssh.nix`) is an example of this. Set per-user HM state (e.g. `xdg.dataFile`) through these helpers — don't set `home-manager.users.<hostname>` attrs directly in modules (it bypasses the `hm`-args convention and duplicates `host.username` lookups).
  - **Gotcha — NixOS-tree HM modules receive NixOS args.** Path entries are imported with the _NixOS_ module args plus the HM config passed explicitly as `hm`, so `config`/`lib` refer to the **NixOS side** and give no HM state or `lib.hm`. Use `hm.config.*`, `hm.config.sops.*`, and `hm.lib.hm.dag.*` for HM-side values (see `_common/zsh.hm.nix`, `_features/rclone/default.nix`, `_features/gaming/default.nix`). Home configs under `home/` (wired via `flake.nix`) and `modules/*.hm.nix` (loaded as `home-manager.sharedModules`) instead get real HM args, so `config`/`lib` are the HM side there.
  - **Gotcha — inline `(hm: {...})` functions receive only `hm`**, nothing else. To use HM-side values inside them reference `hm.config.*` / `hm.lib.hm.dag.*`; to use NixOS-side values (e.g. `config.sops.secrets` paths or `xelib.apps`) close over the enclosing module's args (`config`, `lib`, `xelib`, ...) in a `let` binding or directly.
  - **Gotcha — one inline entry must return a _single flat module_ for `programs.ssh.settings`.** Definitions from separate modules in a `lib.mkMerge` **inside** one inline `(hm: ...)` entry only keep the last one (the `programs.ssh.settings` `dagOf` option), so earlier defs vanish. Separate `importUser` **entries** (and path modules like `local/home-manager.nix`) do merge properly — the issue is only the nested `lib.mkMerge` within a single fn's return value. Fold sub-configs into one attrset with `//`/`lib.recursiveUpdate` (see `xelib.mkSSHConfig`, which returns a folded module) or split them across separate entries (see `_common/ssh.nix` + `_common/git.nix`).
  - `*.hm.nix` files must live in `_common/` (excluded from NixOS import), inside `_features/<f>/`, in `modules/` (split into `home-manager.sharedModules` by the factory), or in a subdir with its own `default.nix` — **never directly in a host dir**, which auto-imports every `.nix` file as a NixOS module.
- **SSH client config**: per-user `~/.ssh/config` is managed only by home-manager `programs.ssh` (NixOS `programs.ssh` configures just system-wide `/etc/ssh/ssh_config`: known hosts, package, defaults — plus the `nvstly-dotfiles` alias block in `_common/git.nix` used by the flake input for the satellite repo, so root/daemon git fetches resolve it too). `programs.ssh.matchBlocks` (and its `extraOptions`) is **deprecated** — use `programs.ssh.settings."<host>"` with CamelCase ssh_config(5) directives (`HostName`, `User`, `Port`, `IdentityFile`, `IdentitiesOnly`, `ForwardAgent`...), `settings."*"` for the default block, and `hm.lib.hm.dag` (in nixos-tree modules) to order blocks. `mkSSHConfig` in `xelib` emits these from the host table. The ssh **key sops secrets are declared on the NixOS side as `sops.groups`** — `ssh_pubkeys` (via `mkSSHSecrets` in `xelib`) and `git_ssh` (in `_common/git.nix`) — so `IdentityFile` points at `config.sops.groupPaths.<group>.<field>` (→ `/run/secrets/<group>-<field>`). The settings themselves stay HM-side. Machine blocks and code-host blocks are each emitted with `hm.lib.hm.dag.entryBefore [ "*" ]` (see `mkSSHConfig` in `xelib` and `_common/git.nix`), so the `"*"` block in `_common/ssh.nix` renders last with no after-list needed.
- **SOPS secrets (`modules/sops.nix` + `xelib/opsecrets.nix`)**: two patterns —
  - `sops.envFiles.<name> = { KEY = "op://..." }` → a single dotenv secret file (`sops/<host>/<name>.env`), usable as `environmentFile`.
  - `sops.groups.<name>.<field> = "op://..."` (or `{ value = ...; ... }`) → individual secrets, resolves to `sops.groupPaths.<group>.<field>`. Access actual file via `config.sops.groupPaths.<group>.<field>` (placeholder via `groupPlaceholders`).
  - **Always use the 1Password item ID (UUID) in `op://` URLs** (e.g. `op://Private/<uuid>/<field>`) — never the item name, which can change.
  - These are declared in modules/hosts; the Go tool reads the evaluated `opSecrets` and writes the SOPS files. After adding a new 1Password-backed secret, run the go tool to regenerate.
  - `sops.opSecrets` exists on the **home-manager side too** (`xelib/opsecrets.nix`); secrets declared there get a `user_` filename prefix (`sops/<host>/user_<name>.yaml`, e.g. `user_rustic.yaml`). The Go tool reads both `conf.config.sops.opSecrets` and `conf.config.home-manager.users.*.sops.opSecrets`, so adding HM-side secrets also requires regenerating. Prefer the NixOS side for secrets shared across users/services (the ssh keys in `_common/ssh.nix` are a deliberate example).
- **Custom packages**: live as overlays in `overlays/` (see layout above), so they're exposed directly on `pkgs`. There is no `xelpkgs` specialArg anymore.
- **`package.nix` convention**: any directory anywhere under a host dir or `_features/` containing `*.package.nix` gets turned into a flake package (`packages.<name>`). Naming: relative path joined with `-` (e.g. `_features/gaming/` → `gaming-<name>`). These are host/feature-scoped, unlike the global `overlays/` packages.
- **`umport`**: loads all files in `modules/` into every host — `*.hm.nix` as home-manager sharedModules, the rest as NixOS modules (the split lives in `entrypoint.nix`).
- **Satellite dotfiles repos (e.g. `nvstly/dotfiles`)**: private repos that import this repo as a flake input and call `lib.mkEntrypoint` (the factory in `entrypoint.nix`) with their own `nixosDir`/hosts data — they reuse everything else from here. This repo consumes their **static data files** (`inputs.nvstly + "/hosts.nix"`, `/apps.nix`; the input is `flake = false`) and merges them: hosts table (`externalHosts`), ssh entries, headscale records. Never evaluate satellite configs from here and never merge satellite apps into `config.apps`. The `nvstly-dotfiles` ssh alias + `git_ssh.nvstly_deploy` deploy key (both in `_common/git.nix`) provide scoped read access; the lockfile pins the rev, so evals stay pure.
- **Impure nixpkgs overlays** (`nixos/common.nix`): `nix.nixPath` adds `nixpkgs-overlays=/etc/nix/nixpkgs-overlays`, whose entries (an `environment.etc` dir) are one thin `import "<store>/overlays/<name>"` wrapper per entry in `overlays/` (file or dir) plus `zz-unstable.nix` — the path is the store snapshot of `overlays/` from the current generation, not `xelib.location` (the mutable repo), so deleting an overlay doesn't break existing wrappers; editing one requires a rebuild before impure evals see it (a bare `unstable` from `<nixpkgs-unstable>`). This is the only way `nix-shell -p` / `nix-build` / `nix-env` see repo overlays — they build their package set from `NIX_PATH`, and the flake's overlays never apply there. nixpkgs loads it only in _impure_ evals, and pure eval can't read NIX*PATH at all, so flakes/`nixos-rebuild`/CI are unaffected. Deploy gotcha: after `nixos-rebuild switch`, existing sessions/tmux keep the old NIX_PATH because `/etc/zshenv`+`/etc/profile` skip `/etc/set-environment` when the inherited `__NIXOS_SET_ENVIRONMENT_DONE=1` marker is set — verify in a truly fresh login (`env -u __NIXOS_SET_ENVIRONMENT_DONE zsh -l`), not just a new tab/window. Two constraints: it must be one overlay per entry (a `.nix` file or a dir whose `default.nix` is imported; nixpkgs `throwIfNot`s that every entry in the dir is a \_function*; folding the list into one `final: prev: ...` breaks the stdenv booter with an infinite recursion, and `lib.mkMerge` doesn't unwrap either — so don't try to consolidate the dir), and the `unstable` import must pass `overlays = [ ]` (otherwise nixpkgs re-applies the same dir inside the unstable instance and `unstable.siyuan` recurses forever via `overlays/siyuan.nix`). `unstable` there is upstream-only, so `unstable.<custom overlay pkg>` is _not_ available. The 3 flake-input overlays (copyparty, nix-vscode-extensions, timefinder-electron) are also absent there. Don't combine with `~/.config/nixpkgs/overlays` — `nixpkgs-overlays` wins and nixpkgs errors if both the home `overlays.nix` file and `overlays/` dir exist.
- **specialArgs**: `extras` (in `mkNixosConfiguration`) gives modules `dns`, `home-manager`, `hostname`, `inputs`, `self`, `system`, `xelib`, plus `host` (= `xelib.hosts.<hostname>`).

## Conventions

- **Do not add service-specific items/instructions to AGENTS.md unless explicitly requested.** AGENTS.md is for repo-wide guidance; keep service details in the service's own config file (e.g. garage notes live in `nixos/hyzenberg/garage/default.nix`).
- **Comment markers** (see `README.md`):
  - `#?INIT:` — something that must be run non-declaratively during machine setup; the `#?`-prefixed lines after it are the commands to run.
  - `TODO:pr` — waiting on a PR merge. `TODO:26.11` — waiting on next nixpkgs release (nixpkgs 26.11).
- Modules should follow the repo's `inherit` alphabetized style and use `lib`/`mkOption` for options.
- Prefer reusing the host table (`xelib.hosts`), `apps`, and the modules in `modules/` over re-declaring per-host configuration.
- Keep app-level customization out of overlays and patches: host-specific env vars, PATH additions, and bundled plugins/extensions belong in the feature module that enables the app. Prefer the app's own extension mechanism (e.g. plugins that shell out to CLIs) over patching its source.
- Secrets: never put plaintext secret values in Nix files. Reference 1Password URIs (always by item **ID**, never item name) and let SOPS/opSecrets handle them.

## Commands / workflow

- Build a host: `nixos-rebuild switch --flake .#<hostname>` (or via `nixosConfigurations`).
- **Never sync/push overlay files to remote hosts (no `rsync`/`scp` of this repo to ehrman or other machines).** The remote checkouts are updated **manually by the user** on request — the agent only edits the local repo, validates it locally (`nix fmt`/`nix eval`), then asks the user to deploy.
- Eval/config checks: `nix eval .#nixosConfigurations.<hostname>.config...`.
- Format the whole repo: `nix fmt` (treefmt, configured in `treefmt.nix`: nixfmt for nix, gofmt for go, shfmt for shell, prettier for everything else). The factory wires treefmt-nix's wrapper as the `formatter` output and its check as `checks.formatting` (so `nix flake check` verifies formatting). Also run via Forgejo CI.
- Regenerate SOPS secrets: run the `sops-build-secrets` tool (requires 1Password desktop app / `OP_SHARED_LIBRARY`).
- CI: `.github/workflows/` builds every host toplevel on push/schedule and pushes to the binary cache (configured via `nixConfig`; see `nixConfig.extra-substituters`/keys). Forgejo workflow auto-commits formatting changes.

## Things to watch out for

- The flake tree only sees _tracked_ files. New modules (e.g. a new host dir or a new directory under `nixos/`) must be `git add`ed before evaluation will see them.
- Host dirs auto-import every `.nix` file as a NixOS module (no `*.hm.nix` exclusion, unlike `_common/`) — keep home-manager modules in `_common/`, `_features/`, `modules/`, or a subdir with its own `default.nix`.
- `nixConfig.extra-substituters`/`keys` need `--accept-flake-config` to take effect in non-NixOS commands. CI relies on this too.
- Keep `nixConfig` in sync with the NixOS `nix.settings.substituters` on each host (both point to the binary cache).
- Some configs intentionally target the `nixos-unstable`/custom branches per-host (see the `unstableHosts` param in `entrypoint.nix`) — don't assume all hosts use the same nixpkgs.
- `.gitignore`: exclude `result` symlinks and qcow2 images.
- Renamed options (nixpkgs `mkRenamedOptionModule`, e.g. `services.frp.enable` → `services.frp.instances."".enable`) **abort** when their config is read — `tryEval` can't catch it. Anything walking `config.services`/`config.programs` must gate on the options tree first and skip invisible (rename-shim) options — see `enabledPackages` in `modules/track-packages.nix`.
- `nix eval --expr` does **not** bind `--arg`/`--argstr` — interpolate values into the expr string instead.
- **Btrfs compression is fs-wide, not per-mount/subvol.** `compress`/`compress-force` live on the superblock; the first mount of the filesystem wins and every later mount silently adopts its values (while `/proc/mounts` shows every mount with the winning options — per-mount compress settings are illusory). `modules/persist.nix` therefore applies one uniform `compress-force=zstd:5` to every btrfs mount. The per-inode `btrfs.compression` xattr (settable via `btrfs property set`/`setfattr`, and via tmpfiles `t` rules) accepts `algo:level` but kernels ≤6.18 honor only the algorithm — the level falls back to the mount option's (verified on 6.18.57); per-subvol levels are a pending patch series (see the `TODO:pr` on `persist.ed.<name>.compression` in `modules/persist.nix`).
- **Impermanence behavior gotchas**: user
  entries deduce their storage path from the entry's mount path — entry `home` at `/z/home`
  puts user data at `/z/home/home/<user>/…` (with the extra `home` segment; don't seed
  `/z/home/<user>/…`). File-level entries (`files`/`userFiles`) become `persist-z-*.service`
  bind units rather than `.mount`s, and they **refuse to run when the target already exists**
  ("A file already exists") — an issue only on hosts without `wipeOnBoot`, where the
  root-subvol originals shadow the bind. One-time fix: delete the stale target files
  (`/etc/machine-id`, ssh host keys, `trusted-settings.json`, …) then start the failed
  units; later boots replay the bind over an empty target on their own.
- Package update tracking: `trackPackages` options (`modules/track-packages.nix`, auto-derives the tracked list, lazily — zero rebuild cost) + `xela-outdated` (`overlays/xela-outdated/`, `nx outdated`) report each package's OURS/TIP vs its own branch's upstream tip (unstable = explicitly pinned from `pkgs.unstable`; classify checks the base instance first so hosts on the unstable base read as stable). It runs one `nix eval` process per host because a single full-fleet eval OOMs 11GB machines.

## Self-documentation

- If, while working on a feature, you have to look something up that isn't specific to
  that feature — a module-system quirk, how the home-manager wiring passes arguments, a
  hidden convention, or an option/package behavior that differs from expectations — add a
  concise note to this file so future agents don't have to rediscover it. Keep it short,
  accurate, and tied to the code it describes (path/line). If it's service-specific,
  leave it in the service's own config file instead (per the Conventions section above).
- LUKS keyfiles on a separate filesystem: `boot.initrd.luks.devices.<name>.preOpenCommands` /
  `postOpenCommands` are **classic stage-1 only** — nixpkgs asserts them away on systemd stage 1
  (see `nixos/modules/system/boot/luksroot.nix` in nixpkgs). With systemd stage 1, mount the
  keyfile's filesystem from `boot.initrd.systemd.services.<name>` hooked directly into the
  cryptsetup instance: `wantedBy = [ "systemd-cryptsetup@${utils.escapeSystemdPath name}.service" ]`
  - `before` it (same pattern as nixpkgs' clevis services in `luksroot.nix`), e.g. the
    `luks-esp` service in `nixos/hyzenberg/hardware.nix` (instance names are crypttab names with
    systemd escapes, dash → `\x2d`). Do NOT use `wantedBy = [ "cryptsetup-pre.target" ]` —
    nothing wants that target (systemd-cryptsetup@.service only orders `After=`), so the hook
    never runs and the unlock silently falls back to a passphrase prompt.
    Also: `neededForBoot` alone does **not** order an initrd mount against a cryptsetup unit —
    relying on it for keyfiles races the cryptsetup unit and silently falls back to a passphrase
    prompt. And evaluating `config.swapDevices` (or other typed options) as a raw JSON value can
    force unrelated lazy consumers (`label` reading) and error even though the toplevel evaluates
    fine — prefer full toplevel eval (`config.system.build.toplevel.drvPath`) when validating.
    Footgun found on hyzenberg: Nix string literals don't support `\xNN` escapes — unknown
    escapes silently drop the backslash, so `"...\x2d..."` evaluates to `...x2d...`. Never
    hand-write unit-name escapes in string literals; produce backslashes via
    `lib.escapeSystemdPath` / `lib.replaceStrings ["-"] ["\\x2d"]`, or (better) keep LUKS
    device attr names dashless (e.g. `cryptroot`) so `systemd-cryptsetup@<name>.service`
    instance references need no escaping at all. Matching device-unit naming case is also
    identifier-type-specific: udev lowercases GPT `by-partuuid` entries (sourced from
    `/sys/.../partuuid`) even though `sfdisk -d` prints uppercase — referencing an uppercase
    partuuid device unit makes `requires` stall into a 90s timeout and a passphrase fallback
    (bit us in `nixos/hyzenberg/hardware.nix`). by-uuid entries keep the case as stored by
    the fs driver (vfat: uppercase like `AC7A-7F39`). Impermanence 7b1d382f `mkRemovedOptionModule`s
    `allowOther`/`method` — those _abort on read_, so a full `--json` dump of
    `environment.persistence` (or per-entry submodule attrsets, which read everything) dies even
    though builds are fine. To inspect persistence wiring, eval string-only views instead:
    `attrNames config.systemd.units` / `config.systemd.units.<name>.text`, glob `var-lib` /
    `home-walt`. Also: the flake tree only sees git-tracked files — a fresh `nixos/<host>/*.nix`
    module silently doesn't load until `git add`ed (bit us with `impermanence.nix`).
